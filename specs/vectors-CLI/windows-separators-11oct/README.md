# The separator in a printed name, on Windows (11 Oct 2026)

The records behind SPEC-CLI 9.8. The genuine `Rar.exe` and `UnRAR.exe`
7.23 for Windows x64 (their sizes and SHA-256 are in `PROGRAMS.json`),
run on a hosted Windows runner by the capture workflow of 6 Oct with
two arms added for this question. 21 commands, none failed
(`COUNTS.txt`, `INDEX.tsv`).

- `separators/made-directories.json`: a member two directories deep
  (`a\b\f.txt`), extracted with `x` under a destination typed with a
  backslash and with a slash, from an archive that holds the directory
  entries and from one that holds the file alone (both kept under
  `separators/made-directories/`), with each destination's tree
  afterwards.
- `separators/listing.json`: a directory `t` with `b.txt`, under each
  listing command (`separators/listing/t.rar`).

Every command has its arguments, its exit and BOTH streams as raw
bytes, in base64 and shown. `SYSTEM.json` is the runner's own account
of itself. The programs are not here: they were fetched on the runner
from their maker and never copied off it.
