# Evidence records for specification F, 6 Oct 2026

Everything here was made by running the reference programs as black boxes,
or by reading bytes of archives they wrote. The reference of record is
`rar` and `unrar` 7.23 for x86-64 Linux (sha256 `56c3c4fd...` and
`926d3a00...`); where a record also names macOS it is the 7.23 build for
aarch64 macOS. No program's source was read to make any of it.

| File or directory | What it is | How to run it again |
|---|---|---|
| `census.py`, `census.txt` | A container walker written from specification F sections 3.1 to 3.5, and its count over the 248 genuine archive files kept in this repository (every header checksum, block type, flag bit, field value and record type). | `python3 census.py > census.txt` |
| `rar5-genuine-writer.py`, `rar5-genuine/` | 54 small RAR 5 archives written by reference `rar` 7.23, one per switch that changes what a header carries (links, file copies, the metadata record, file versions, owner records, time record forms, volumes, standard input), the commands (`COMMANDS.txt`) and the census of them (`CENSUS.txt`). | `python3 rar5-genuine-writer.py --rar RAR --out DIR`, then `python3 census.py --dir DIR` |
| `probekit.py` | Byte builders for both containers, written from the specification's text, and the runner that puts an archive to `unrar lt`, `unrar t`, `unrar p`, `rar lt` and `rar t` and records the answers. | used by the probes |
| `rar5-container-probe.py`, `rar5-container/` | 165 constructed archives (RAR 5, and a few of the older containers for detection), one field or one rule altered in each. `<arm>/x.rar` is the archive, `<arm>.txt` the full record, `summary.txt` one line per program per arm (Linux), `summary-macos.txt` the same on macOS. The two differ only in the time zone of printed times and in one arm's printing of bytes that are no text (`decoy-rar13`). | `python3 rar5-container-probe.py --unrar UNRAR --rar RAR --out DIR` |

| `old-container-probe.py`, `old-container/` | 178 constructed archives of the RAR 1.5 to 4 container and of RAR 1.3, recorded the same way. The two systems differ only in the printing of bytes that are no text (`r13-garbage-after`). | `python3 old-container-probe.py --unrar UNRAR --rar RAR --out DIR` |
| `cmt5-compressed-probe.py`, `cmt5-compressed/` | A RAR 5 comment and compression (3.2.9 S4, S5): `WRITTEN.txt` is what `rar` 7.23 put in the `CMT` header of 21 archives written at `-m0` to `-m5`; the ten arms are constructed archives whose `CMT` header declares method 1, 3 or 5 over a stream genuine `rar` packed, recorded like the container probes. `WRITTEN-macos.txt` and `summary-macos.txt` are the macOS run: the same but for the zone of printed times. One process at a time, `rar` at `-mt1`. | `python3 cmt5-compressed-probe.py --rar RAR --unrar UNRAR --out DIR` |
| `file-comment-span.py`, `file-comment-span.txt` | Which bytes the checksum of a FILE header covers when it embeds a comment (3.3.1 F3): the spans that fit the two such headers of the genuine `d250_fc.rar` of DOS RAR 2.50, and the reference's answer to that archive and to a copy checksummed over the whole header |
| `type-75-census.py`, `type-75-census.txt` | Whether any genuine archive of the RAR 1.5 to 4 container holds a type 0x75 block between blocks (3.3.3 B2): every block type at the top level of the 169 kept files and of 49 more written by the old builds with comments, and where each comment block sits. One thread, no decoder. | `python3 type-75-census.py`; `python3 type-75-census.py DIR` |
| `volume-census.py`, `volume-census.txt`, `rar5-genuine/VOLUME-CENSUS.txt` | What the split members of the 23 genuine volume sets kept here, and of the 4 written for this specification, show: repeated fields, each fragment's checksum field, where the split flags sit, numbering. | `python3 volume-census.py > volume-census.txt`; `python3 volume-census.py --dir rar5-genuine` |
| `volume-probe.py`, `volume-sets/` | 43 constructed two volume sets (four added on 7 Oct 2026 for 3.5.6 C4, after the others), one rule broken in each, recorded like the other probes; the two systems give the same answers. | `python3 volume-probe.py --unrar UNRAR --rar RAR --out DIR` |
| `solid-probe.py`, `solid/` | 114 arms on solid archives: RAR 5 ones written by the reference `rar` for the probe (`solid/WRITTEN.txt` lists each as written) and the genuine solid archives of `fixtures/legacy/archives`, with one flag, one bit, the order or presence of whole blocks, an inserted header or one data byte changed in each. Recorded like the container probes; `summary-macos.txt` and `WRITTEN-macos.txt` are the macOS run, whose verdicts are the same (the written archives differ by a few packed bytes). | `python3 solid-probe.py --unrar UNRAR --rar RAR --out DIR` |
| `solid-census.py`, `solid-census.txt` | Where the archive solid flag and the member solid bit sit in every genuine archive kept here, member by member, and the counts section 3.6 quotes. | `python3 solid-census.py > solid-census.txt` |
| `links-probe.py`, `links/` | 97 arms of what `unrar` does ON DISK with link and copy members (3.8): each archive is extracted into a fresh directory beside a file no archive should be able to change, and the record holds the commands, their output and the tree as the run left it. `summary-macos.txt` is the macOS run; the two differ in the host's matters only (a link's own time, the longest target a link may hold, what a hard link to a symbolic link becomes). It uses one fixed absolute directory, `/tmp/spec-f-links-probe-victim`, made and removed by the run. | `python3 links-probe.py --unrar UNRAR --out DIR` |
| `overwrite-probe.py`, `overwrite/` | 47 arms of what `unrar` does when an output path is already taken (3.9): each overwrite switch, and each answer fed to the question, with the raw bytes of both streams. `summary-macos.txt` is the macOS run, the same but for a directory's size in one question. | `python3 overwrite-probe.py --unrar UNRAR --rar RAR --out DIR` |
| `earlier-probes-linux/` | What three earlier probes (`../zero-byte-member-probe.py`, `../orphan-chain-probe.py`, `../legacy-volume-and-solid.py`) print under the Linux reference. | run each from `specs/vectors-F` with `rar` and `unrar` on the path |
| `ver-switch-probe.sh`, `ver-switch-linux.txt` | What `-ver` and `-ver<n>` select (3.2.6.4, V5 to V7): one file written five times with `rar a -ver` and with `-ver2`, listed and extracted under each form of the switch and with each form of the name; the answers of rar and unrar 7.23 for x86-64 Linux, the same on macOS. |

Archives above 64 KiB are rebuilt by each run and not kept; their records
are. Times in the Linux records are printed in UTC and in the macOS records
in that machine's zone.
